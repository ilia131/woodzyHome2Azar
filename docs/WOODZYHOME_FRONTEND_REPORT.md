# گزارش پیاده‌سازی فرانت‌اند WoodzyHome

۲۷ نمای مستقل در پروژهٔ Next.js ایجاد شده‌اند. هشت نمای فروشگاه بر اساس سند هندسهٔ Figma ساخته شده‌اند. حساب، خرید و مدیریت از همان سرویس‌های Django REST Framework استفاده می‌کنند. فهرست زیر وضعیت مسیرها و حدود آزمون هر نما را نشان می‌دهد.

## وضعیت هر صفحه

«آزمون مسیر» شامل HTTP 200، عنوان اصلی، فارسی و RTL و نبود خطای جاوااسکریپت است. «Responsive» در این جدول یعنی بررسی جابه‌جایی منوی موبایل و دسکتاپ و نبود اسکرول افقی سراسری در Chromium با اندازه‌های ۳۲۰×۸۱۲، ۳۷۵×۸۱۲، ۳۹۰×۸۴۴، ۷۶۸×۱۰۲۴، ۱۰۲۴×۷۶۸، ۱۲۸۰×۹۰۰ و ۱۴۴۰×۹۰۰. جدول‌های عریض داخل ظرف خود اسکرول می‌شوند.

## فایل‌ها و اجزای مشترک

- برنامهٔ جدید `frontend/` شامل تنظیمات Next.js و TypeScript، فایل قفل، نمونهٔ محیط، راهنما، دارایی‌های تصویری و آزمون‌های Playwright است.
- `frontend/src/app/` شامل مسیرهای فروشگاه و گروه‌های حساب، پرداخت و مدیریت، Server Actionها، مسیر پیشنهاد جست‌وجو و وضعیت‌های خطا است.
- `frontend/src/components/` شامل Header، Footer، کارت و شبکهٔ محصول، گالری، فیلتر کاتالوگ، جدول صفحه‌بندی‌شده، فرم عملیات و پوستهٔ مشترک صفحات مدیریت و حساب است.
- `frontend/src/features/` شامل رفتارهای حساب، خرید، مدیریت و فهرست صریح عملیات مجاز در فرانت‌اند است.
- `frontend/src/lib/` شامل کلاینت مرکزی DRF، درخواست‌های دارای JWT سمت سرور، انواع کاتالوگ و دادهٔ مجزای حالت پیش‌نمایش است. RTK Query پیشنهادهای جست‌وجو را از مسیر هم‌مبدأ دریافت می‌کند.
- [نگاشت فریم‌ها](FIGMA_SCREEN_MAPPING.md) و این گزارش اضافه شده‌اند. [سند طراحی](WOODZYHOME_DESIGN_SPEC.md) و [پیوست هندسه](WOODZYHOME_FIGMA_GEOMETRY.tsv) مرجع باقی مانده‌اند.

## نتیجهٔ اجرای تست

| بررسی | نتیجه |
|---|---|
| نصب پاک `npm ci` | موفق، ۴۲ بسته |
| `npm run typecheck` | موفق |
| `npm run build` | موفق روی Next.js 16.4.6 |
| `npm test` با Django ایزوله | ۳۴ موفق، صفر ناموفق و صفر ردشده |
| `npm test` در حالت پیش‌نمایش | ۲۹ موفق، صفر ناموفق و ۵ سناریوی وابسته به Django اجرا نشدند |
| بررسی پاسخ API | ۳۹ درخواست خواندن به DRF، همگی HTTP 200 |
| بررسی قرارداد API | خواندن OpenAPI 3.0.3 با ۸۴ مسیر و کنترل ۱۰ مسیر نمایندهٔ فروشگاه، حساب، پرداخت و مدیریت |
| بررسی وابستگی تولید `npm audit --omit=dev --audit-level=high` | ۰ آسیب‌پذیری گزارش‌شده |

اجرای اولیهٔ فشرده از یک IP مشترک به پاسخ ۴۲۹ رسید. واکشی پیش‌دستانهٔ پیوندهای پرتعداد کاتالوگ غیرفعال شد و پاسخ عمومی کاتالوگ برای بازه‌ای کوتاه قابل کش شد. در اجرای نهایی سقف درخواست فقط در تنظیمات موقت Django برای آزمون مرورگر افزایش یافت. پیکربندی بک‌اند پروژه و پایگاه دادهٔ موجود دست‌نخورده ماندند. این اجرا ظرفیت تولید یا رفتار محدودکنندهٔ نرخ پشت پراکسی را تأیید نمی‌کند.

## محدودیت‌های تحویل

- بازیابی رمز برای کاربری که وارد نشده و تغییر وضعیت سفارش توسط مدیر به API بک‌اند نیاز دارند. عملیات احرازشدهٔ تغییر رمز و مشاهدهٔ مدیریتی سفارش در دسترس‌اند.
- خبرنامه و فرم تماس API ندارند. نشانی، شماره و اطلاعات واقعی نمایشگاه هنوز در اختیار این رابط نیست. در بخش مشتریان صفحهٔ نخست به دیدگاه‌های ثبت‌شدهٔ محصول پیوند داده شده است.
- درگاه‌های واقعی در بک‌اند آماده نیستند. فهرست آمادگی درگاه‌ها از API کارکنان در مدیریت خوانده می‌شود. API عمومی فهرست درگاه‌ها در بک‌اند وجود ندارد. ایجاد پرداخت و سناریوهای این رابط از درگاه Mock همان پروژه استفاده می‌کنند. اجرای تست روی Django ایزوله با SQLite بوده و شامل استقرار Compose یا بازبینی رقابت PostgreSQL نیست.
- تطبیق پیکسلی و جزئیات بصری Figma به دلیل محدودیت ارتباط تأیید نشده‌اند. پالت و Vazirmatn جایگزین موقت‌اند و در فایل توکن‌ها قرار دارند. تصاویر ویراستاری برای پیش‌نمایش‌اند. لوگوی رسمیِ قابل‌استفاده را می‌توان با `WOODZY_LOGO_PATH` متصل کرد.
- فقط مرورگر Chromium آزمایش شد. عملکرد همهٔ فرم‌ها و همهٔ نقش‌ها به‌صورت E2E بررسی نشده‌اند. نشست در این رابط پس از انقضای access token به ورود مجدد نیاز دارد.
