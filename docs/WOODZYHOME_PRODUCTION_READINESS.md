# WoodzyHome Production Readiness و Design Completion

**وضعیت انتشار عمومی: نیازمند تکمیل.** چهار قابلیت مرحله قبل در Django و Next.js افزوده شدند و برنامه روی سرویس‌های ایزوله اجرا شد. تحویل دارایی‌های تأییدشده، SMTP واقعی، ورودی HTTPS و استقرار کامل Compose هنوز باز هستند.

## ۱. طراحی و تصاویر

هشت صفحه از روی هندسهٔ رسمی Figma با اجرای واقعی مرورگر مقایسه شدند. درخواست تازهٔ Design Context و Screenshot میزبان Figma با محدودیت طرح Starter رد شد. رنگ و تایپوگرافی از روی تصاویر موقت قطعی فرض نشده‌اند. لوگوی رسمی بدون فایل قابل استفاده به پروژه اضافه نشده است. تصاویر نهایی محصولات نیز به فایل‌ها یا دادهٔ رسانهٔ تأییدشده برای SKUهای کاتالوگ نیاز دارند. اجرای متصل تصویر محصول و دسته را از Django دریافت می‌کند. اجرای ثبت‌شده در تصاویر از نسخهٔ پیش‌نمایش و تصاویر موقت استفاده می‌کند.

در عرض ۱۲۸۰، عرض ستون گالری و ستون متن هیرو، اندازهٔ تصویر بنر نشیمن و ارتفاع ناوبری علاقه‌مندی‌ها بر اساس هندسهٔ تأییدشده اصلاح شدند. گالری محصول اکنون حدود ۶۸۰٫۶۶ × ۵۴۴٫۵۲، تصویر بنر نشیمن ۴۹۳٫۳۳ × ۳۵۲ و سربرگ علاقه‌مندی‌ها ۱۸۳ پیکسل است. فوتر هر هشت نمونه ۳۹۰ پیکسل شد. اختلاف ارتفاع کل به ترکیب محتوای پویا، فاصله‌گذاری بخش‌ها و نبود رندر مرجع نیز وابسته است و تطبیق پیکسلی تأیید نشده است.

## ۲. امکانات افزوده

| قابلیت | API زیر `/api/v1/` | رفتار تأییدشده |
|---|---|---|
| بازیابی رمز | `POST auth/password/recovery/` و `confirm/`، ثبت و تأیید ایمیل در `email/` و `email/confirm/` | ایمیل بازیابی با رمز فعلی و تأیید مالک حساب ثبت می‌شود. پاسخ درخواست وجود حساب را اعلام نمی‌کند. کد منقضی یا تکراری رد می‌شود و پس از تغییر رمز، JWT قبلی و Refresh Token از اعتبار می‌افتند. |
| تغییر وضعیت سفارش | `PATCH admin/orders/{id}/status/` | نیازمند کارمند با مجوز تغییر سفارش، تراکنش و قفل ردیف و وضعیت مورد انتظار. لغو سفارش در انتظار پرداخت رزرو را با سرویس قبلی آزاد می‌کند. گردش انجام سفارش از پرداخت‌شده به آماده‌سازی و سپس تکمیل است. عملیات موفق در Audit Log ثبت می‌شود و تعارض پاسخ ۴۰۹ دارد. |
| تماس | `POST store/contact/` | پیام معتبر با محدودیت نرخ در PostgreSQL ذخیره می‌شود. صندوق در Django Admin و تحت مجوز مشاهده در دسترس است. |
| خبرنامه | `POST store/newsletter/` و `confirm/` | عضویت یا لغو عضویت پس از تأیید کد ایمیل. تغییر وضعیت نسخهٔ کد را عوض می‌کند و بازپخش رد می‌شود. |

برای بازیابی حساب موجود، ابتدا باید ایمیل بازیابی تأیید شده باشد. ایمیل‌های پروفایل قبلی به‌طور خودکار قابل بازیابی نشده‌اند. تنظیمات ایمیل بدون `TRANSACTIONAL_EMAIL_ENABLED=1` غیرفعال هستند. کدها و درخواست‌ها از طریق Celery ارسال می‌شوند و پذیرش درخواست به معنی تحویل ایمیل نیست.

## ۳. زیرساخت و امنیت

| بررسی | نتیجه |
|---|---|
| PostgreSQL | 17.12 بومی و ایزوله. مهاجرت به‌وسیلهٔ نقش Migration، Gunicorn با نقش Runtime. |
| Migration | مهاجرت تازه و ارتقا از نسخهٔ قبلی accounts/core موفق. دادهٔ حساب نمونه حفظ شد. `migrate --check` و `makemigrations --check --dry-run` موفق. |
| نقش‌های پایگاه داده | هر دو نقش فاقد Superuser، Create DB و Create Role. CRUD Runtime داخل تراکنش rollback تأیید شد. پنج عملیات ممتاز شامل ایجاد نقش، پایگاه داده، جدول، تغییر مالک schema و حذف رکورد مهاجرت با `42501` رد شدند. |
| Redis و Celery | Redis 7.0.15 با `PONG`. Worker به ping پاسخ داد و وظایف ایمیل ثبت شدند. Beat در اجرا کارهای انقضای رزرو و مغایرت پرداخت را ارسال کرد. |
| Docker Compose | `docker compose --profile deploy config -q` موفق. ساخت کانتینر آزمایشی با خطای فضای دیسک daemon و کد 125 متوقف شد. استقرار Compose و دادهٔ موجود تغییر نکرد. Compose فعلی سرویس Next.js ندارد. |
| چک امنیت Django | `check --deploy --fail-level WARNING` با HTTPS، Secure Cookie، HSTS، origin و host نمونه در تنظیمات ایزوله بدون هشدار اجرا شد. TLS و مسیر پراکسی دامنهٔ نهایی هنوز نیازمند اعتبارسنجی هستند. |
| CORS و CSRF | CORS در اجرای ایزوله برای مبدأ مجاز هدر بازگرداند و برای مبدأ بیرونی هدر بازنگرداند. ارسال POST ورود Django Admin بدون توکن CSRF پاسخ ۴۰۳ داشت. اعتبارسنجی دامنهٔ نهایی انجام نشده است. |
| پرداخت | شروع برنامه در حالت Production با Mock فعال رد شد. دور کامل پرداخت در آزمون فقط از درگاه شبیه‌سازی استفاده کرد. فعال‌سازی درگاه واقعی به مستندات رسمی و دسترسی معتبر نیاز دارد. |
| OpenAPI | تولید و اعتبارسنجی ۹۲ مسیر با `spectacular --validate` موفق. |
| تست بک‌اند | ۱۲۷ آزمون موفق روی PostgreSQL 17.12 و Redis. |
| تست فرانت‌اند | Build و TypeScript موفق. ۳۵ آزمون Playwright روی Django و PostgreSQL ایزوله موفق. چرخهٔ خرید با Mock، تغییر وضعیت اداری، تماس، حساب و آدرس‌ها، موجودی، SEO و تعدیل نظر پوشش داده شدند. |

برای خودکارسازی آزمون‌های مرورگر، سقف نرخ فقط در فایل تنظیمات موقت محیط ایزوله افزایش یافت. SMTP خارجی، ظرفیت تولید، اجرای همهٔ سرویس‌ها در Compose و HTTPS نهایی تأیید نشده‌اند.

## ۵. فایل‌ها و موارد باز

- بک‌اند شامل تغییرات `accounts/recovery.py`، `accounts/models.py`، `accounts/urls.py`، مهاجرت جدید Accounts، `core/store_api.py`، `core/store_mail.py`، `core/admin.py`، `core/models.py`، مهاجرت جدید Core و `core/test_store_readiness.py` است.
- گردش سفارش در `orders/lifecycle.py`، `orders/admin_api.py` و `orders/inventory.py` به‌روزرسانی شد. مجوزها و تنظیمات در `core/management/commands/provision_roles.py`، `config/settings.py`، `config/urls.py`، `.env.example` و `docker-compose.yml` ثبت شده‌اند.
- فرانت‌اند شامل Server Action و فرم‌های جدید در `frontend/src/app/store-actions.ts` و `frontend/src/components/store-forms.tsx`، اتصال در صفحات خانه، حساب، تماس و مدیریت، توکن‌های هندسه و آزمون و اسکریپت ثبت تصویر است.
- برای اتمام بصری، فایل رسمی لوگو، تصاویر تأییدشدهٔ محصولات، دسترسی Inspect/Design Context یا خروجی استایل‌ها و رندرهای Figma موردنیازند. اطلاعات واقعی نمایشگاه نیز هنوز به محتوا نیاز دارد.
- برای انتشار، رلهٔ SMTP با هویت و دامنهٔ تأییدشده، تست تحویل، ingress HTTPS و سیاست پراکسی، ظرفیت دیسک و اجرای کامل Compose لازم‌اند. هیچ پرداخت یا پیام خارجی واقعی در این مرحله انجام نشد.
